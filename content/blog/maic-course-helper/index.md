在 MAIC 上学习时，真正消耗时间的有时不是课程内容，而是在课程列表、章节页和课堂页面之间反复切换：确认哪些课程还没完成，打开下一个模块，等待课件加载，再回到列表检查进度。

[MAIC 课程进度助手](https://github.com/canxin121/maic-course-helper-public) 是一个运行在浏览器中的 Tampermonkey 用户脚本。它在 `www.maic.tsinghua.edu.cn` 页面右下角增加一个小面板，用来汇总课程与学习进度，并在用户打开总开关后自动推进 PPT 课件和视频。

这个项目的定位比较明确：把重复的课程导航和播放操作交给脚本，但把测验和需要用户判断的内容留给用户自己完成。它不会自动答题，也不会自动提交测验。

## 它解决了什么问题

安装脚本后，面板主要提供四类能力：

- 合并项目课程、公开课程和学习进度，生成一份课程清单。
- 缓存课程与模块状态，打开页面时优先显示已有结果。
- 通过一个“自动刷课”总开关，自动推进 PPT 页面和视频模块。
- 识别测验，并在测验前停下来，不代替用户答题或提交。

课程清单中的状态会尽量具体地展示出来，例如课件已经完成多少页、视频完成了多少、还剩几个测验，或者当前课程是否因为接口错误而暂时无法判断。这样打开 MAIC 后，第一眼就能知道下一步该做什么。

## 安装

1. 安装 [Tampermonkey](https://www.tampermonkey.net/) 浏览器扩展。
2. 点击[安装 MAIC 课程进度助手](https://github.com/canxin121/maic-course-helper-public/raw/main/maic-course-helper.min.user.js)。
3. 在 Tampermonkey 的安装页面确认安装。
4. 打开 [MAIC](https://www.maic.tsinghua.edu.cn/)，页面右下角会出现“MAIC 课程进度助手”。

脚本的匹配范围限定为 `https://www.maic.tsinghua.edu.cn/*`，不会在其它网站运行。发布仓库提供的是压缩后的用户脚本，更新时重新点击同一个安装链接即可，Tampermonkey 会按照脚本元数据中的更新地址检查新版本。

## 基本使用方式

### 先读取课程清单

首次使用或切换项目后，点击“刷新课程”。脚本会读取当前登录用户和项目上下文，然后获取项目课程、公开课程、我的学习进度以及每门课程的模块信息。

课程数据会存进浏览器的本地缓存，并且缓存键包含用户 ID 和项目 ID。换用户或换项目时不会把上一组课程直接混在当前清单里。下次打开页面时，脚本会先显示缓存，之后再根据需要刷新最新进度。

### 打开自动推进

确认课程清单无误后，点击“自动刷课：关闭”按钮，将总开关切换为开启。脚本会从当前项目中寻找尚未完成的课程和模块：

```text
读取课程清单
    -> 找到第一个未完成模块
    -> 进入 PPT 或视频课堂
    -> 使用页面原生控件推进
    -> 刷新服务端进度
    -> 进入下一门课程，或在测验前暂停
```

在 PPT 课堂中，脚本会等待页面控件出现，并根据当前状态点击可用的下一页、下一节或完成控件。对带有音频的课件，它也会处理继续播放和重新播放等原生控件。

视频课堂则会等待播放器元数据可用，把播放位置推进到结尾前约 5 秒，再恢复播放并等待站点记录完成状态。课程完成后，脚本会重新读取当前课程的进度；服务端确认完成后，才会继续寻找下一门可处理的课程。

### 遇到测验会停下

测验是这个项目刻意保留的人工环节。脚本会根据课程状态和模块类型识别测验：如果下一步是测验，自动流程会暂停，并在面板中提示用户完成测验。完成后点击“刷新课程”，脚本就能重新判断课程状态。

这条边界很重要。自动推进页面和播放器，只能减少重复操作；它不应该代替用户理解课程内容、回答问题或提交结果。

## 代码里比较值得注意的设计

### 只调用允许的读取接口

脚本内部维护了一个只读接口白名单，目前包括：

- `course/list/projectcourses`
- `course/list/publiccourses`
- `course/curriculum`
- `course/module/list`

课程清单和进度判断依赖这些接口，脚本自己的 API 客户端会拒绝调用白名单之外的路径。真正的课件推进则通过页面已经存在的按钮和播放器完成，让 MAIC 自己处理原本的进度记录逻辑，而不是伪造一套独立的提交协议。

读取课程时，模块列表最多并发处理两门课程；请求之间至少间隔约 650 毫秒，单次请求超时为 20 秒，失败时最多重试三次。如果站点返回 `429`、频繁请求提示或 `Retry-After`，脚本会按服务端提示或指数退避等待，而不是继续密集请求。

这套限制会让首次读取不一定很快，但可以减少刷新课程时给站点造成突发请求的机会，也让“暂时被限流”与“课程真的没有数据”这两种状态更容易区分。

### 缓存的是浏览器里的课程副本

缓存使用 `localStorage` 保存，键名包含当前用户和项目，当前缓存结构版本为 `4`。缓存的作用是让面板可以快速展示上一次读到的课程列表，之后再进行更新；它不是服务器上的新数据源，也不会把课程进度上传到第三方服务。

脚本需要在当前 MAIC 页面中读取登录上下文，并用同源请求访问 MAIC 的接口。用户脚本使用 `@grant none`，运行域名也限制在 MAIC 官方站点。代码中没有把 Cookie、Token 或课程数据发送到项目作者自己的服务器。

### 自动流程有状态判断和恢复上限

自动化最容易出问题的地方不是“点击一次按钮”，而是页面加载慢、按钮暂时不可见、服务端还没写入进度，或者播放器停在一个看似完成但实际未同步的状态。

脚本会检查按钮是否可见、是否正在加载、是否处于禁用状态，并在课件完成后等待服务端进度变化。如果课堂页面大约 45 秒没有有效进展，它会尝试重新打开当前课堂；连续恢复最多三次，仍然没有变化就暂停自动流程，避免浏览器不断刷新同一个页面。

当页面被切换到后台时，浏览器仍可能降低定时器频率。脚本会尝试使用 Worker 定时器，并在面板中显示后台运行状态，但这并不能绕过所有浏览器的后台节流规则。需要稳定运行时，最好让 MAIC 页面保持在可见标签页中。

### 用 Shadow DOM 隔离面板样式

助手的界面挂载在独立的 Shadow DOM 中，面板的按钮、课程列表和状态样式不会直接污染 MAIC 页面原有的 CSS。面板支持收起，课程列表和状态区域也有自己的滚动范围，开启自动推进后，课程按钮会暂时禁用，避免在自动流程中手动跳到另一门课程。

## 0.1.7 版本需要知道的一点

当前公开仓库中的脚本版本是 `0.1.7`。除了 README 中列出的课程缓存、PPT/视频推进和测验保护外，自动流程还会在页面出现相关高级设置时，将“课堂讨论活跃度”选择为“低”，并使用 MAIC 页面自己的“保存”按钮提交这个选择。这个行为没有单独的面板开关。

如果某门课程对课堂讨论活跃度有明确要求，开启自动刷课前应先确认这个默认行为是否符合课程规则。

## 适合什么场景

这个脚本更适合以下情况：

- 课程数量较多，需要快速确认哪些项目还没有完成。
- 课程由大量 PPT 页面或视频模块组成，重复点击下一页和继续播放比较繁琐。
- 希望把课程状态集中显示在一个面板中，而不是反复打开不同页面核对。
- 接受测验、作业和其它需要理解与判断的环节由自己完成。

如果只是偶尔打开一门很短的课程，手动操作可能更直接。自动化也不是对所有课程都适用：站点页面结构、播放器行为和接口返回字段发生变化后，脚本可能需要更新。

> [!WARNING]
> 使用前请确认所在课程或平台规则允许这类浏览器自动化。不要使用脚本规避测验、作业、签到或其它考核要求。遇到页面行为异常时，可以先把“自动刷课”切换为关闭，刷新页面，并通过 [GitHub 仓库](https://github.com/canxin121/maic-course-helper-public) 查看最新版本和问题反馈。
